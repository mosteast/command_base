# `yaml_patch` 通用 YAML 结构化编辑需求

- 日期：2026-07-17
- 状态：待审
- 目标版本：现有 v1 之后的下一阶段能力
- 适用对象：任意有效 YAML 文件，不绑定任何仓库、字段名或业务模型

## 1. 目标

`yaml_patch` 应提供可查询、可组合、可验证且可证明的 YAML 结构化编辑能力，同时保留未授权修改范围之外的原始字节。

本工具必须在没有项目配置时处理通用 YAML。项目可以选择提供版本化 profile，用声明式规则表达字段类型、身份、引用、图约束、字段顺序和诊断投影。核心不得预设 `id`、`name`、`requires`、子节点键或任何业务语义。

本文使用以下约束词：

- “必须”表示实现和验收不可缺少。
- “应”表示默认实现要求；不满足时必须给出书面理由和等价保护。
- “可以”表示可选能力，不得改变未启用时的核心行为。

## 2. 需求边界

### 2.1 通用核心

通用核心负责：

- YAML 源文件读取、解析、资源隔离和源位置索引。
- 与业务字段无关的结构查询和结果投影。
- 映射、序列、标量、映射对和完整子树的结构编辑。
- 单文件与多文件事务、前置条件、变更上限和事务内句柄。
- 候选结果验证、字节证明、预览、锁、写入和恢复。
- 版本化 CLI、程序库 API、JSON 协议、错误码和能力发现。

### 2.2 可选声明式 profile

profile 负责声明项目希望额外执行的规则，但不得改变 YAML 的语法含义。profile 可以声明：

- 文件包含和排除规则。
- 节点集合及其字段、类型、基数和字段顺序。
- 一个或多个简单或复合身份约束。
- 不可变字段、受保护节点和删除策略。
- 引用解析、引用完整性和有向图约束。
- 字段别名、迁移规则、警告与错误级别。
- 诊断和审计输出允许展示的字段。

没有 profile 时，上述项目规则不得隐式生效。

### 2.3 扩展接口

P1 可以提供显式注册的可信验证扩展。CLI 不得扫描仓库并自动执行插件代码。通过 CLI 启用的扩展必须显式授权、版本固定、隔离运行、受时间和内存限制，并在 manifest 中记录名称、版本和结果。程序库内注册的可信回调由调用方负责信任边界，但回调只能返回诊断，不能直接修改候选字节。

## 3. 当前 v1 基线

现有 v1 已具备以下可复用基础：

- UTF-8、BOM、换行模式、UTF-16 到字节位置映射和源摘要。
- 固定解析器版本、保留 CST 源令牌、解析诊断归一化和隔离 worker。
- 文档、结构路径、节点类型、原始标量和源位置查询。
- 稳定排序、结果数量限制、输出字节限制、分页和临时 locator。
- `scalar-token`、`node-value`、`mapping-value` 三种单范围编辑。
- 完整候选文件解析、锚点/别名边界检查、no-op、文本 diff 和字节证明。
- dry-run 默认、显式 `--write`、并发锁、同目录临时文件和原子替换。
- 文件模式、所有者、部分扩展属性、文件和目录同步及写后摘要验证。
- 版本化成功/失败 JSON envelope、严格 CLI 选项和能力发现。

本需求不要求推翻这些机制。新增能力应复用现有源索引、验证、证明和 writer 边界，并对不兼容协议使用新版本。

- **profile 可选规则**：不能成为核心默认，但应能通过通用 profile 表达。

## 5. 总体架构

```text
CLI / 程序库 API
        |
        v
版本化请求协议 -----> 可选 profile / 显式可信扩展
        |                         |
        v                         v
查询与投影 -------> 事务规划与操作编译 -------> 候选工作快照
                                                |
                         +----------------------+
                         v
                语法验证 + profile 验证
                         |
                         v
                diff + 语义摘要 + 字节证明
                         |
                         v
              dry-run 或锁定、提交、恢复
```

CLI 和程序库 API 必须调用同一套请求解析、查询、操作编译、验证和证明逻辑。CLI 不得复制一套弱化的验证路径，程序库 API 也不得绕过写入前置条件。

## 6. P0：通用结构查询

### 6.1 可寻址对象

Q-001. 查询必须能够寻址 YAML 流、文档、映射、映射对、映射键、映射值、序列、序列项、标量和别名。

Q-002. 查询必须区分节点类型与标量值类型。标量值类型至少包括字符串、整数、浮点数、布尔值和空值，并保留原始标量文本用于精确源比较。

Q-003. 默认不得展开别名。需要按别名目标查询时，调用方必须显式指定解析模式，结果必须同时标明别名位置和目标位置。

### 6.2 查询 AST

Q-004. 查询必须使用有版本号的 JSON AST，不能依赖不稳定的命令行表达式解析。

Q-005. 谓词至少支持：

- 节点类型和标量值类型。
- 类型化等于、不等于和集合包含。
- 字段存在、不存在、字段值和字段类型。
- 文档编号、结构路径、源文件和源位置。
- 父节点、祖先、后代和兄弟关系。
- 深度、直接子节点数和后代节点数。
- 原始标量文本和原始字节摘要。

Q-006. 多个谓词必须支持明确的 `all`、`any` 和 `not` 组合。协议不得依赖对象键顺序表达布尔优先级。

Q-007. 精确、类型化匹配必须是默认行为。正则、大小写折叠、Unicode 规范化或数值范围匹配必须显式指定，并受时间、模式长度和结果数量限制。

Q-008. 字段谓词命中映射内的键值时，查询必须能返回承载该字段的映射节点，而不只返回字段值标量。

### 6.3 结果选择与投影

Q-009. 查询必须能够从匹配节点选择 `self`、父节点、指定层级祖先、映射键、映射值、指定字段、子节点集合或兄弟节点集合。

Q-010. 结果投影必须显式列出需要返回的字段。内置投影至少包括源路径、文档、节点类型、结构路径、行列、字节范围、原始摘要、父路径和兄弟位置。

Q-011. profile 可以补充诊断投影字段，但核心不得将任意字段名判断为安全或特殊字段。

Q-012. 投影遇到不存在的字段时必须根据请求的 `missing` 策略返回空值、忽略该字段或报错，不得隐式切换行为。

### 6.4 基数、排序与定位器

Q-013. 所有写操作都必须具有预期匹配数约束。单目标操作省略该字段时，协议必须将其规范化为精确匹配 1 个；批量操作必须显式声明精确数量或上下界及最大数量。

Q-014. 实际匹配数不满足预期时必须在写入前失败。不得默认选择第一个匹配。

Q-015. 候选诊断必须包含核心位置字段、祖先路径和显式投影。候选数量和输出字节必须受限制，超限时返回截断状态和继续查询所需的游标。

Q-016. 跨文件结果必须按规范化源路径、文档编号、起始字节和遍历序号稳定排序。相同输入、profile 和工具版本必须产生相同顺序。

Q-017. 分页必须使用绑定输入文件摘要集合与查询摘要的游标。源文件或查询变化后继续使用旧游标必须返回冲突，不能返回错位页面。

Q-018. 查询可以返回不透明临时 locator。locator 必须包含或绑定协议版本、源摘要、文档、结构位置、字节范围和目标摘要，不得承诺跨源修改长期有效。

Q-019. locator 只能用于同一源快照。事务内跨操作引用必须使用事务句柄，不得依赖旧 locator 或可变化的序列索引。

## 7. P0：通用结构编辑

### 7.1 映射操作

E-001. 映射操作必须支持新增映射对、修改值、删除映射对、重命名键和移动或重排映射对。

E-002. 新增映射对必须支持前置、追加、指定索引、指定目标之前和指定目标之后。

E-003. profile 可以声明建议字段顺序。显式位置优先于 profile 顺序；未提供显式位置时才可以使用 profile 顺序；两者都没有时必须采用有文档记录的稳定默认位置。

E-004. 重命名键必须只改变目标键的声明字节范围及必要的语法前缀。值、注释和其他映射对不得被重新序列化。

E-005. 复杂键必须通过映射对索引、摘要或 locator 寻址。工具不得把所有映射键假设为唯一字符串。

### 7.2 序列操作

E-006. 序列操作必须支持追加、前置、指定位置插入、目标前后插入、删除、交换、重排和同文件或跨文件移动。

E-007. 序列值操作必须支持“仅当不存在时追加”“删除一个精确值”“删除所有精确值”和“检查重复值”。比较必须复用类型化查询语义。

E-008. 序列位置必须在执行该操作时针对当前工作快照解析。负索引、越界索引和目标消失必须按协议明确失败，不能被静默修正。

### 7.3 标量操作

E-009. 标量操作必须支持原始令牌替换和类型化值设置。

E-010. 原始令牌替换必须把调用方提供的内容视为 YAML 源，并对完整候选文档重新解析。

E-011. 类型化值设置必须默认保留原有普通、单引号、双引号或块标量样式，以及块标量的 chomping 和缩进指示符。若新值无法在原样式下安全表示，操作必须失败，除非请求显式允许指定的新样式。

E-012. 类型化 no-op 以解析后的类型和值相同且源策略无需改变为准；原始 no-op 以目标字节完全相同为准。两者都不得引发文件写入。

### 7.4 子树操作

E-013. 子树操作必须支持新增、删除、复制和移动完整节点，目标可以是同文件或不同文件中的映射或序列位置。

E-014. 移动必须携带节点的全部字段、后代、标签、锚点和确定归属于该节点的注释，不得通过业务字段白名单重建节点。

E-015. 工具必须发布确定性的注释归属规则。预览必须显示移动范围；未明确归属于节点的独立分隔注释不得被静默移动。

E-016. 子树内部原始字节必须保持不变。允许变化的内容仅限源移除范围、目标插入所需的列表标记或映射语法、每一物理行的结构缩进前缀，以及调用方显式要求的修改。

E-017. 对块标量、显式缩进指示符、流式集合、文档指令、自定义标签、锚点或别名无法证明安全重定位时，移动必须以 `UNSUPPORTED_EDIT_SHAPE` 或 `CROSS_BOUNDARY_DEPENDENCY` 失败。

E-018. 跨文档或跨文件移动不得形成悬空别名、重复锚点或不可解析的标签句柄。验证必须覆盖源候选和目标候选的完整文档。

### 7.5 删除与保护

E-019. 核心删除操作只依赖显式选择器、基数和前置条件，不得猜测节点是否已同步、是否重要或是否可以删除。

E-020. profile 可以将任意节点集合、字段存在条件或身份状态声明为受保护。受保护节点的删除、复制或身份修改必须在候选提交前失败。

E-021. 删除包含锚点、被外部别名引用或被 profile 引用的节点时，必须拒绝或在同一事务中证明所有依赖已被安全更新。

## 8. P0：事务语义

T-001. 一个事务可以包含多个文件和多个有序操作。事务请求必须有独立版本号和稳定 JSON schema。

T-002. 所有操作按声明顺序作用于当前工作快照。每个选择器和前置条件在对应操作执行前解析。不得由实现自行选择“初始快照”或“当前快照”语义。

T-003. 需要在修改前绑定节点时，事务必须提供显式 `bind` 能力。`bind` 产生事务内句柄，后续操作可以引用该句柄。

T-004. 新增、复制或移动操作必须能够为结果节点分配事务内句柄。句柄必须跟随节点跨序列重排和跨文件移动。

T-005. 事务句柄仅在该事务内有效，不得序列化成跨事务永久 locator。

T-006. 语法正确性、字节范围安全和句柄一致性必须在每个操作后检查。允许暂时违反的 profile 业务规则必须在最终候选验证阶段全部恢复；profile 可以要求每个操作后也满足指定规则。

T-007. 相同事务、相同输入摘要、相同 profile 和相同工具版本必须产生相同候选字节、diff、语义摘要和证明。

T-008. 所有参与文件必须在规划阶段确定。提交阶段不得因为插件或查询结果临时扩大文件集合。

T-009. 操作不得读写声明文件集合之外的 YAML 源。发现未声明依赖时必须停止并要求重新规划事务。

### 8.1 前置条件

T-010. 事务级前置条件至少支持参与文件集合摘要、profile 摘要、工具协议版本和最大变更预算。

T-011. 文件级前置条件至少支持路径、文件摘要、文件身份和文档数量。

T-012. 操作级前置条件至少支持预期匹配数、目标摘要、旧原始值、旧类型化值、父节点句柄、相邻节点句柄和目标位置。

T-013. 任一前置条件失败时，事务不得进入写入阶段。错误必须指出预期值、实际值和失败作用域，但不得无上限输出源内容。

### 8.2 变更上限

T-014. 事务必须支持限制参与文件数、操作数、匹配节点数、变更范围数、新增节点数、删除节点数、移动节点数、每文件和总修改字节数。

T-015. profile 声明身份后，还必须支持限制新增、删除、修改和受影响身份的数量。

T-016. 所有限制必须在 dry-run 和 write 使用相同算法。超过限制必须返回 `CHANGE_LIMIT_EXCEEDED`，并在任何写入前停止。

## 9. P0：无损保证与字节证明

L-001. 候选文件必须由原始字节切片和显式替换字节构成。不得为了结构编辑而重新序列化完整文件或完整文档。

L-002. 每个操作必须声明一个或多个原始范围和候选范围。最终证明必须覆盖所有范围，并证明这些范围并集之外的字节保持不变。

L-003. 多个范围重叠、交叉、顺序不确定或与声明操作不一致时，事务必须在候选生成阶段失败。

L-004. 必须保留未授权范围中的注释、空行、键顺序、引号、转义、标签、锚点、别名、块标量样式、换行字节、BOM、文档分隔符、结尾换行和 Unicode 编码字节。

L-005. 字节证明必须包含格式和版本、原始及候选文件摘要、每个范围的原始和替换摘要、未变区域摘要、删除/插入/触碰字节数和 no-op 状态。

L-006. 跨文件事务必须为每个文件生成证明，并生成绑定全部文件摘要和操作顺序的事务总摘要。

L-007. 完全相同的最终候选是成功 no-op。no-op 可以生成 manifest 和验证结果，但不得获取写锁、创建替换临时文件、调用 rename 或改变任何源文件元数据。

L-008. 无法证明范围外字节不变时，必须返回 `BYTE_GUARANTEE_FAILED`，不得降级成全文件格式化。

## 10. P0：安全写入与多文件恢复

W-001. dry-run 必须是默认行为。只有显式 `--write` 且未指定 `--dry-run` 时才能修改源文件。

W-002. 单文件写入必须使用同目录临时文件、文件同步、原子替换、目录同步和写后摘要验证。平台不支持时必须在写前返回 `ATOMIC_WRITE_UNAVAILABLE`。

W-003. 写入前必须验证文件仍是预期的普通文件、文件身份与摘要未变，并处理符号链接和多硬链接风险。

W-004. 必须保留文件模式、所有者和组。扩展属性、ACL 或其他检测到的元数据只有在可证明复制时才能继续；否则必须在替换前拒绝写入。

W-005. 并发锁必须由随机令牌拥有，记录进程、主机、工具版本、操作和时间。释放或清理只能删除当前令牌拥有的锁。

W-006. 清理过期锁必须先检查锁详情，显式提供匹配令牌，并证明同主机进程已不存在。工具不得按年龄自动删除锁。

W-007. 多文件事务必须按规范化真实路径的稳定顺序获取全部锁，避免不同事务因锁顺序不同形成死锁。

W-008. 获得全部锁后必须重新读取并验证所有参与文件、所有前置条件和最终候选，然后才能准备临时文件。

W-009. 在第一次源文件替换前，必须持久化并同步事务日志。日志至少包含事务 ID、状态、参与路径、原始及候选摘要、临时文件、恢复副本、提交顺序和每文件进度。

W-010. 多文件状态机必须至少区分 `planned`、`prepared`、`committing`、`committed`、`rolling_back`、`rolled_back` 和 `recovery_required`。

W-011. 正常验证失败或准备失败不得改变任何源文件。提交开始后的失败必须自动尝试回滚或完成提交，并在日志中记录每一步。

W-012. 系统无法保证多文件同时原子可见时，文档和结果不得声称具有该保证。允许崩溃期间短暂出现混合版本，但必须能通过日志和恢复副本重复执行恢复，最终达到全部原始版本或全部候选版本。

W-013. 必须提供只读事务状态检查和显式恢复命令。恢复命令必须幂等，并拒绝摘要或文件身份与日志不一致的文件。

W-014. 退出前无法恢复一致状态时，必须返回 `RECOVERY_REQUIRED`、日志路径、已提交文件、未提交文件和下一步命令。不得把部分完成报告为成功。

## 11. P0：通用验证

V-001. 所有源文件和候选文件必须接受完整 YAML 解析。新增解析错误、未经允许的警告、无效别名或不一致的标签句柄必须阻止写入。

V-002. 验证必须受文件字节、节点数、深度、时间、内存和别名解析限制。资源超限不得导致主 CLI 进程失控。

V-003. 核心验证不得要求特定根类型、字段名、字段类型、层级模型或引用模型。

V-004. profile 必须是有版本号的 YAML 或 JSON 声明文档，并有自己的 schema、摘要和严格未知字段检查。

V-005. profile 可以用文件 glob 和忽略 glob 定义作用域。路径包含空格、方括号和其他特殊字符时必须正确处理；显式文字路径不得被误解释为 glob。

V-006. profile 的节点集合必须由通用查询 AST 定义，不能依赖核心内置业务类型。

V-007. 字段规则至少可以声明允许字段、必需字段、可选字段、值类型、基数、同一字段类型一致性和子节点集合类型。

V-008. 身份规则必须支持任意字段路径或字段组合、允许缺失/空值策略、类型、唯一性作用域和已有非空身份不可变策略。

V-009. 核心不得生成业务值或身份值。为新节点设置受身份规则约束的非空值时，必须由请求明确提供，并满足 profile 声明的普通模式或显式外部同步模式。

V-010. 编辑前后身份比较必须检测已有身份被修改、删除、遗漏或复制。移动节点不应被计为身份变化，但必须验证其身份和所有后代身份仍唯一。

V-011. 引用规则必须声明源节点集合、源字段、标量或序列基数、目标节点集合、目标身份、允许空值策略和解析作用域。

V-012. 引用验证必须检测类型错误、重复值、目标不存在、目标不唯一和悬空引用。

V-013. profile 可以把引用关系声明为有向图并要求无环。检测到环时必须返回包含源路径、节点投影和每条边来源的可读循环路径。

V-014. 字段别名规则必须声明规范键、别名键和严重级别。迁移前可以是 warning；迁移操作只能改变明确命中的键令牌及必要语法。

V-015. 验证范围必须支持全部输入文件、指定文件、变更节点、变更文件和受影响引用闭包。局部验证结果必须说明未验证的范围，不能冒充完整验证。

V-016. 写入事务必须至少验证所有候选文件和 profile 判定受影响的引用闭包。profile 无法可靠计算闭包时必须退回完整作用域验证。

V-017. 每条诊断必须包含稳定错误码、严重级别、规则 ID、源文件、文档、行列、结构路径、违反规则和建议动作。profile 可以增加节点投影，但不得替换核心定位信息。

## 12. P0：预览、审计与协议

### 12.1 预览

D-001. dry-run 必须同时提供人类可读文本 diff、版本化结构化 JSON diff 和语义摘要。

D-002. JSON diff 必须逐文件列出操作类型、源和目标 locator 或句柄、原始与候选范围、类型化前后值、字节统计和 no-op 状态。敏感值可以由投影策略隐藏，但摘要和证明仍必须可验证。

D-003. 语义摘要必须描述新增、删除、复制、移动、重排和字段修改，以及源父节点、目标父节点和位置变化。

D-004. profile 声明身份或引用后，摘要必须列出保留、增加、删除或修改的身份数量，以及新增、删除、修复或破坏的引用数量。

D-005. 任何违反身份、引用或图不变量的变化必须在写入前失败，不能只显示警告后继续，除非 profile 对该具体规则明确配置为 warning 且该规则不属于写入安全前置条件。

### 12.2 Manifest

D-006. 每次 dry-run 和 write 都必须能生成版本化 manifest。manifest 至少记录请求摘要、查询、投影、前置条件、操作、参与文件、profile 摘要、扩展版本、限制、验证结果、diff 摘要和字节证明。

D-007. manifest 必须区分请求内容和运行结果，避免重放时把旧结果当成新前置条件。

D-008. manifest 重放必须重新验证源摘要、profile 摘要、工具能力和全部前置条件。任何变化必须返回冲突，不能覆盖新内容。

D-009. manifest 和结构化输出必须稳定排序。时间、随机事务 ID 和绝对临时路径等非确定字段不得参与可复现内容摘要。

### 12.3 协议兼容性

P-001. 查询、操作、事务、profile、manifest、字节证明和 JSON envelope 必须分别声明版本。不同 artifact 不得因为共享一个数字而被迫同时升级。

P-002. 已发布版本的字段含义不得静默改变。不兼容查询、操作或多范围证明必须使用新版本；实现可以同时读取旧版本和新版本。

P-003. CLI `capabilities` 必须报告支持的协议版本、操作、编辑单元、profile 规则、资源限制、writer 保证和恢复能力。

P-004. 程序库 API 必须使用与 CLI 相同的普通对象协议和错误对象。所有公开导出优先使用命名导出，并遵循仓库命名规则。

P-005. JSON 成功结果必须包含 `ok`、协议版本和 `result`。失败结果必须包含 `ok: false`、协议版本、错误码、消息、可恢复性、建议动作和结构化详情。

P-006. 机器 JSON 输出不得包含 ANSI 颜色或非 JSON 日志。人类模式可以使用颜色；debug 阶段和 IO 日志必须写入 stderr。

P-007. `--quiet` 只输出警告和错误；`--debug` 在每个阶段和 IO 前输出诊断；未知选项必须失败。

P-008. `-h, --help`、`-v, --version`、`--debug` 必须支持。`--version` 只能输出版本号。`--write` 默认 false，`-d, --dry-run` 必须能强制禁止写入。

P-009. 所有接受文件的命令必须支持 glob，并正确处理含空格和特殊字符的路径。输出目录、事务日志和工具生成文件必须从默认源 glob 中排除，避免重复处理自身产物。

P-010. 生成查询、计划、manifest、事务日志或其他工具产物的命令，默认不得覆盖已存在的输出。只有显式 `--refresh` 才能替换已验证为同类工具产物的目标；不得用 `--refresh` 覆盖普通源文件或未知目录。

P-011. `--query -` 和 `--operations -` 必须从 stdin 读取一个 UTF-8 JSON 文档。一个命令有多个输入参数同时指定 `-` 时必须拒绝，除非该命令定义了包含所有输入的单一 envelope。

P-012. 保存查询和命名快捷命令必须存储版本、查询 AST、投影和默认基数，不得把字段名或项目路径硬编码进核心命令。

### 12.4 错误码与退出码

P-013. 至少稳定区分以下错误类别：

- 查询：`NO_MATCH`、`AMBIGUOUS_MATCH`、`EXPECTATION_FAILED`。
- 冲突：`SOURCE_CHANGED`、`TARGET_CHANGED`、`PRECONDITION_FAILED`。
- 验证：`VALIDATION_FAILED`、`PROFILE_VIOLATION`、`IDENTITY_VIOLATION`、`REFERENCE_VIOLATION`、`CYCLE_DETECTED`。
- 结构与限制：`UNSUPPORTED_EDIT_SHAPE`、`CROSS_BOUNDARY_DEPENDENCY`、`CHANGE_LIMIT_EXCEEDED`。
- 写入与恢复：`UNSAFE_CONCURRENCY`、`ATOMIC_WRITE_UNAVAILABLE`、`BYTE_GUARANTEE_FAILED`、`RECOVERY_REQUIRED`。
- 协议与内部：`PROTOCOL_VERSION_UNSUPPORTED`、`INTERNAL_ERROR`。

P-014. 下一协议版本的 CLI 退出码必须固定为：成功及 no-op 为 `0`；请求或协议错误为 `2`；查询基数或前置条件冲突为 `3`；YAML 或 profile 验证失败为 `4`；并发冲突为 `5`；限制、结构或能力不支持为 `6`；写入、证明或恢复失败为 `7`；未归类内部错误为 `70`。

P-015. 同一错误码不得在不同版本中被重新解释为不兼容的失败类别。新增详情字段必须保持向后兼容。

## 13. P1：迁移与批处理

M-001. 迁移计划必须支持映射键别名统一、字段类型转换、值包装或解包、子结构键统一和节点移动。

M-002. 迁移规则必须由查询 AST 和通用操作组成。内置迁移不得包含具体字段名、文件路径或业务类型。

M-003. 计划模式默认只扫描、验证和报告，不写入。报告必须给出匹配数、冲突数、预计文件数、字节数和无法安全处理的结构。

M-004. 批处理必须支持稳定分批、每批文件/节点/字节限制、批次 manifest、断点恢复和重复执行 no-op。

M-005. 每批写入前必须验证本批候选；整个迁移完成前必须执行声明的全局验证。全局规则在中间批次可能暂时不满足时，manifest 必须记录迁移状态，普通写入模式不得把该状态当成有效仓库。

M-006. 恢复必须区分“重试当前批”“回滚当前批”“从已提交批继续”和“从头重新规划”。源或 profile 摘要变化后不得盲目续跑旧计划。

M-007. P1 程序库 API 必须允许其他脚本复用查询、事务规划、候选验证、证明和 writer，而不是调用 CLI 并解析人类文本。

## 14. 性能与资源要求

R-001. 所有解析、查询和验证必须有有限的默认文件字节、节点数、深度、结果数、输出字节、运行时间和内存限制。提高限制必须显式请求。

R-002. 正则和图遍历必须有独立限制，防止复杂模式、超大引用闭包或循环图耗尽资源。

R-003. 基准数据必须是与任何业务无关的合成或脱敏 YAML，并覆盖深层映射、序列、重复普通字段值、多文档、Unicode、注释、块标量、标签、锚点和别名。

R-004. 基准至少包含两个规模：

- 基线规模：不少于 14 个文件和 64,000 个语法节点；最大文件不少于 2 MiB 和 30,000 个节点。
- 增长规模：不少于基线节点数和总字节数的 10 倍。

R-005. 每份基准结果必须记录 CPU、内存、存储类型、操作系统、Node.js、解析器和工具版本，以及冷启动/热启动、样本数和 p50/p95。

R-006. 在已记录的参考机器上，基线规模热启动完整验证 p95 应低于 3 秒，单个最大文件查询 p95 应低于 1 秒。其他机器使用相对回归而不是这些绝对数字判定。

R-007. 相同参考环境中的性能回归超过 20% 必须由变更说明解释。结果正确性、写入安全和资源上限不得为达到性能目标而降低。

R-008. 增长规模必须在配置的硬限制内完成或以明确的限制错误停止，不得崩溃、无限运行或产生无上限输出。

## 15. 必须覆盖的验收场景

### 15.1 查询

- 唯一字符串字段定位成功；重复值返回有界候选并拒绝单目标写入。
- 按数字、布尔值和空值定位承载字段的完整映射，不能与同文本的字符串混淆。
- 组合文件、祖先、深度、字段存在和子节点数量条件得到稳定结果。
- 全局排序和游标分页在多文件上无重复、无遗漏；源变化后旧游标返回冲突。
- `--query -` 正常读取 stdin；两个输入同时占用 stdin 时给出稳定请求错误。
- 映射包含复杂键时可以通过映射对索引和摘要定位，不错误使用字符串键快捷路径。

### 15.2 编辑与无损

- 修改一个普通标量、单引号标量、双引号标量及 `|`、`|-`、`>` 块标量，只改变证明中的范围。
- 向任意映射新增字段，不生成请求中不存在的字段或值。
- 字段重命名只改变目标键令牌，不重排或重新格式化完整映射。
- 序列追加唯一值、删除指定值、交换和完整重排均保留未修改项字节。
- 移动包含未知字段、后代、注释、标签和身份投影的完整子树后，内部字节仅发生经证明的结构缩进变化。
- 块标量或跨边界锚点/别名无法安全移动时拒绝操作，不降级成重新序列化。
- 多个顺序操作通过事务句柄引用前一步创建或移动的节点，序列索引变化不导致误编辑。
- 完全相同的单操作和多操作结果均为 no-op，源 inode、mtime、模式和内容不变。
- 声明范围并集外的字节证明覆盖前、中、后多个未变区域。

### 15.3 Profile

- 无 profile 时，包含任意字段名和不同层级结构的有效 YAML 可以查询和编辑。
- profile 将任意字段声明为身份后，已有身份被修改、删除或复制时拒绝写入；移动不视为身份变化。
- profile 声明复合身份时，在配置作用域内正确检测重复组合。
- 新节点未提供身份时不生成虚构值；显式提供的值按 profile 模式验证。
- 任意命名的引用字段出现悬空目标、错误类型、重复值或有向环时拒绝写入并输出路径。
- 字段别名迁移只改变目标键；warning 到 error 的严重级别由 profile 控制。
- 根、中间和叶节点共享字段定义的规则只在 profile 明确声明的节点集合中生效。

### 15.4 写入、并发与恢复

- extract 或 dry-run 后发生并发修改，write 返回源冲突而不是覆盖新内容。
- 多文件事务任一文件在提交前验证失败，所有源文件保持原状。
- 多文件提交在第一个替换后注入失败，自动恢复到全旧或完成到全新；日志状态与文件摘要一致。
- 进程在每个事务状态点崩溃后，恢复命令可以重复运行并达到一致终态。
- 锁令牌不匹配、其他主机锁或仍存活进程的锁均不能被删除。
- 源文件含无法保留的扩展属性或 ACL 时，在 rename 前失败。
- writer 不支持的平台明确返回能力错误，dry-run 仍可使用。

### 15.5 YAML 回归语料

- 中文、日文、组合字符、emoji 和不同 Unicode 长度均保持正确字节位置。
- UTF-8 BOM、LF、CRLF、CR、混合换行和有无结尾换行均有回归测试。
- 普通、引号、转义、块标量、流式集合、多文档、注释、指令、自定义标签、锚点和别名均有回归测试。
- 文件名和目录名包含空格、方括号、通配符字符和非 ASCII 字符时，文字路径与 glob 行为明确且安全。
- 超大文件、超深节点、过多结果、输出过大、复杂正则和超大引用闭包均以对应限制错误停止。

## 16. 明确非目标

- 工具不生成数据库 ID、业务编号或任何未在操作中明确提供的语义值。
- 工具不判断内容是否自然、正确、合理、重复或适合某个业务流程。
- 工具不因字段值相同就判定节点重复，也不自动合并内容。
- 工具不猜测哪个字段是名称、身份、子节点、引用或排序字段。
- 工具不在未明确授权时格式化完整文件、修复别名、排序字段或改变内容语义。
- 工具不保证所有文件系统都支持安全写入，也不把多文件提交描述成不可实现的同时原子可见。
- 通用结构和 profile 验证不替代人工审查或领域专用质量检查。
- 下一阶段不要求 CLI 自动发现或执行仓库内任意代码插件。

## 17. 完成标准

本需求阶段完成必须同时满足：

- 所有平台无关的 P0 条目都有实现、聚焦测试和稳定协议说明。文件系统与元数据等平台相关保证必须在 capability 中准确报告，不支持的写入必须在修改源文件前失败。
- 第 15 节场景全部进入自动化测试，其中单文件测试与多文件故障注入测试分开运行。
- 现有 v1 功能的聚焦回归测试继续通过；不兼容能力使用新 artifact 版本。
- 基准数据、环境记录和结果可在仓库内复现。
- CLI help 包含 Usage、Description、Options、所有枚举值和带注释的 Examples。
- 规范性条目不包含 material 专用字段名、路径、语言规则或项目默认行为；原始示例字段名只能出现在背景和评估说明中。
